# AI_USAGE — LAB 07

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

---

## ครั้งที่ 1

**ถามอะไร**
ถามวิธีทดสอบการเปลี่ยนโหมดเป็น production, ความหมายของ Spread Operator (`...`) ในการดัก Error, และวิธีทำ Challenge เรื่องการสร้างคลาส `AppError` (CP14 & Challenge)

**AI ตอบว่าอย่างไร (สรุปสั้น)**
แนะนำวิธีสลับ `NODE_ENV` ในไฟล์ `.env` อธิบายว่า `...` ใช้แทรกข้อมูลแบบย่อใน Object (เพื่อซ่อน stack trace) และช่วยแก้บั๊กเรื่องตัวแปรที่ตกหล่นในฟังก์ชัน `errorHandler` พร้อมสอนวิธีใช้ `next(new AppError(...))` ใน `notFound`

**ใช้ส่วนไหน / แก้เองตรงไหน**
นำไปปรับใช้ในไฟล์ `.env` และอัปเดตโค้ดใน `api/src/middleware/errorHandler.js`

**เข้าใจโค้ดที่ได้มาไหม** ✓ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

---

## ครั้งที่ 2

**ถามอะไร**
ถามวิธีเขียน Automated Test (CP16) ให้ครบ 6 เคส, ให้ช่วยเช็คความเรียบร้อยของ `API_CONTRACT.md`, และขอโครงร่างสำหรับทำเอกสาร `API_TEST.md`

**AI ตอบว่าอย่างไร (สรุปสั้น)**
ให้โค้ดการทดสอบด้วย `supertest` ครบทั้ง 6 กรณี (GET, POST แบบสำเร็จ/ล้มเหลว และ CORS) พร้อมอธิบายหลักการ assert นอกจากนี้ยังช่วยสแกนหาเศษ template (`>`) ที่ลืมลบใน API Contract และร่างเอกสารทดสอบให้

**ใช้ส่วนไหน / แก้เองตรงไหน**
นำไปเขียนใน `api/tests/app.test.js` เพื่อรัน `npm test`, ลบข้อความที่ตกค้างใน `API_CONTRACT.md`, และสร้างไฟล์ `API_TEST.md`

**เข้าใจโค้ดที่ได้มาไหม** ✓ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## สรุป

- **ส่วนที่เขียนเองทั้งหมด:** การแคปรูปส่งงาน (Network Tab, Error State), การทำเช็คลิสต์ก่อนส่ง, และการจัดการข้อมูลทั่วไปใน API Contract
- **ส่วนที่ AI ช่วย:** การเขียน Automated Test 6 เคสด้วย `supertest`, การสร้างและปรับแก้ Centralized Error Handling (`AppError`), และการรีวิวความถูกต้องของเอกสาร Markdown
- **ส่วนที่ยังไม่มั่นใจ:** (เว้นว่างไว้เติมเองได้เลยครับ เช่น เรื่องลำดับการทำงานของ Middleware)
